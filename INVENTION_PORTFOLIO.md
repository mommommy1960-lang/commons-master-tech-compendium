# Commons Invention Portfolio

Status: working registry for evidence-based development  
Branch scope: draft review only; no item is represented as deployed, certified, or commercially ready.

## Evidence vocabulary

- **DOCUMENTED** — described in a Commons source document.
- **DESIGN** — architecture or specifications exist.
- **SOFTWARE PROTOTYPE** — executable code exists, but production readiness is not established.
- **SIMULATION** — behavior is modeled without proving physical performance.
- **BENCH CANDIDATE** — can be reduced to a present-day laboratory experiment.
- **PHYSICAL PROTOTYPE** — requires dated build records, measurements, photographs, BOM, and reproducible test logs.
- **VALIDATED** — requires independent replication or qualified external review.
- **VISIONARY** — useful future concept containing mechanisms not demonstrated by current evidence.

A finished manuscript, blueprint, DOI, signature, repository, or passing unit test is not proof that a physical invention works.

## Parallel development lanes

### Lane A — maintain the eleven repository drafts

Every repository retains default-deny capability boundaries, consent/revocation where applicable, auditability, adversarial tests, and evidence-aware release gates. Drafts stay unmerged until their required tests execute and produce replayable logs.

### Lane B — no-cost software products

Prioritize CUP, CERL-Preemptive, Pattern Core software, PLI, Sandbox research tools, and Compendium documentation. Each candidate needs installation instructions, license review, examples, tests, security boundaries, and a defined user.

### Lane C — digital twins before hardware

Prioritize the MPRS gripper and low-voltage Safety Master simulation. Physical fabrication follows only after hazards, sensing, failure states, and acceptance criteria are modeled.

### Lane D — laboratory candidates

QCL, Manhattan, adaptive windows, sensing, and metamaterial experiments require independent safety and scientific review. Begin with models, null hypotheses, calibration plans, and instrument requirements.

### Lane E — long-horizon research

Flux/IMR, QCV, Aurora propulsion, Phasing Biomechs, Bioforge, and related concepts remain visible but cannot claim physical feasibility without new reproducible evidence.

## Portfolio priority rule

Advance every family every review cycle, but not with equal resources:

1. Preserve and classify.
2. Define the smallest falsifiable or usable deliverable.
3. Implement software or simulation.
4. Produce reproducible evidence.
5. Seek independent review.
6. Fabricate only after safety and feasibility gates.
7. Offer a product only when its claims match observed evidence.

## Human-time protection

The founder is not a message bus. Technical reviewers communicate through concise decision packets and permanent review records. Escalate only decisions requiring human values, money, legal authority, external communication, hazardous physical work, or release approval.
